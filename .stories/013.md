# Story 013: The result cards share one frame, one copy feedback and one keyed button, instead of writing each three to six times

## Symptom

Three parts of the result cards are written out again in each card.

1. **Copy feedback, three times.** It is in `src/components/FieldCard.tsx:31-50`,
   `src/components/ResultCard.tsx:58-70` and `src/components/WifiCard.tsx:31-41`.
   Each card keeps a `copied` state and a `useEffect` that resets it with
   `setTimeout(…, 1500)` (`src/components/FieldCard.tsx:34-38`,
   `src/components/ResultCard.tsx:60-64`, `src/components/WifiCard.tsx:33-37`).
   The three copies do not behave the same:
   - **The timer.** FieldCard stores a new object for each copy, so a second
     copy restarts the timer (`src/components/FieldCard.tsx:31-32`).
     ResultCard and WifiCard store `true`. A second copy sets the same value,
     React skips the render, and Copied ends 1500 ms after the *first* copy.
   - **A failed copy.** FieldCard and ResultCard show the reason in a
     `p.failure` (`src/components/FieldCard.tsx:44`,
     `src/components/FieldCard.tsx:86`, `src/components/ResultCard.tsx:68`,
     `src/components/ResultCard.tsx:103`). WifiCard drops it:
     `() => undefined` (`src/components/WifiCard.tsx:41`). A failed password
     copy shows nothing at all.
2. **The card frame, five times.** It is in `src/components/FieldCard.tsx:54-63`,
   `src/components/ResultCard.tsx:81-88`, `src/components/WifiCard.tsx:54-61`,
   and the not-found and error cards in `src/App.tsx:109-113` and
   `src/App.tsx:122-126`. Each one writes the card element with its tone, a
   `header.card-head`, the label and headline, and `<DismissButton>`.
3. **Each keyed button names its key twice, six times.** The button is wrapped
   in `<Keyed shortcut="…">`, which prints the keycap
   (`src/components/Ink.tsx:52-61`). The button then names the same key again
   for screen readers.
   - The three ghost Copy buttons write
     `aria-keyshortcuts={SHORTCUTS.copy.aria}`
     (`src/components/FieldCard.tsx:88-98`,
     `src/components/ResultCard.tsx:105-109`,
     `src/components/WifiCard.tsx:74-78`).
   - The three primary buttons pass `keyshortcuts={SHORTCUTS.….aria}` to
     `PrimaryButton`, which writes `aria-keyshortcuts`
     (`src/components/Ink.tsx:41`). These are Open in Maps
     (`src/components/FieldCard.tsx:100-104`), Open
     (`src/components/ResultCard.tsx:112-116`) and Connect
     (`src/components/WifiCard.tsx:80-84`).

## Evidence

nothing. Each of the three duplications is there as the request says. Five
details differ from the request, or are not in it.

### Where the code differs from the request

   > .meta + .headline`. That is true of the three result-card files. The
   not-found and error cards are different (`src/App.tsx:109-113`,
   `src/App.tsx:122-126`):

   rendered DOM stays exactly as it is. So the one Card component renders all
   three shapes, and AC5 holds each one. Moving the App cards to the result
   cards' shape would change the DOM, which this story forbids.
2. **PrimaryButton also writes `aria-keyshortcuts`.** It does so at

### Behaviour changes: there are two, not one

The coordinator decided the first one. The second follows from having one
hook.

- **A: the Wi-Fi card shows a failed copy.** It shows it the way FieldCard
  and ResultCard do: a `p.failure` child of the card, before `.actions`,
  whose text is `String(reason)`. A later copy that succeeds removes it.
  This was the coordinator's decision, delegated by the human.
- **B: on the link, text and Wi-Fi cards, a second copy restarts the timer.**
  Copied then lasts 1500 ms from the last copy, as it already does on the
  contact, phone, SMS and location cards. One hook means one behaviour. The
  restart is the one the code means on purpose: FieldCard has a comment for
  it (`src/components/FieldCard.tsx:31`), and an existing test that must pass
  unchanged holds it (`src/__tests__/ResultCard.test.tsx:200-225`). Keeping
  the old non-restart on two cards would need a hook with two modes. That is
  the duplication this story removes.

  **Coordinator's choice (delegated by the human, 22 Oct 2026): change B is
  accepted.** It makes the seven cards behave the same, and an existing test
  already holds it. AC1 (b) stays.

## Known weakness of the instrument

- **Where code lives, not whether it is good.** AC2 to AC4 prove that the
  timer, the frame and the keyed attribute each sit in one place, and that
  the cards import that place. They do not prove the new code is simpler or
  well named.
- **What the counts resist.** Comments do not count.
  `window.setTimeout` and `globalThis.setTimeout` count, because the match
  is on the word, not on a call shape. `1_500` counts. An alias still names
  `setTimeout` once where it is made, and the cards may not keep an effect.
  A shared constant used by a card's own `<header>` is caught by the
  `<header` count.
- **What the counts do not resist.** A name built from pieces
  (`"card" + "-head"`, `"aria-" + "keyshortcuts"`,
  `globalThis["set" + "Timeout"]`) goes unseen. So does a delay made without
  a timer (a promise chain, `requestAnimationFrame`). The reviewer reads the
  diff for these.
- **Comment removal.** A comment stripper that ignores context could misread
  JSX text that holds an apostrophe or `//`. On the base no `.tsx` file in
  the domain has either outside a comment.
- **Failure handling is not counted.** It is not asserted to sit in one
  place. AC1 holds its behaviour on three cards. The Wi-Fi card is not
  tested for:
  - which comes first, its copy failure or "Could not connect: …", when
    both show;
  - whether Connect clears a copy failure.
- **AC1 mocks onCopy.** It renders `ResultCard` alone in jsdom, with fake
  timers. The real clipboard (`ipc.copyText`, the Tauri plugin) is not
  exercised. What a real failure's reason reads like on a Mac was never
  observed. Enter-to-copy goes through the same function, and that path is
  held by `src/__tests__/AppKeys.test.tsx:137-145`, not by AC1.
- **The DOM guard has limits.** AC5 compares against literals the builder
  copies from the base. If they were copied from the refactored DOM, the
  guard would protect the wrong thing, so the reviewer runs the file on
  b4c520a. The outline leaves out:
  - the dismiss button's `svg`;
  - the inside of `p.content`, `ul.warnings`, `ul.fields` and `div.secret`;
  - every style.

  It covers thirteen cards in their first state. A hidden network, Connecting…
  or Connected, or a card showing a failure, is not in it.
- **Nothing is drawn.** jsdom does no layout and evaluates no `:has()`.
  Visual sameness, faint keycaps included, rests on the DOM being the same.
  A person glances at the popover.
- **Not observed.**
  - `?raw` on a `.tsx` file under this Vitest config. It is used for `.md`,
    `.json` and `.html` (`src/__tests__/docsDescribeApp.test.ts:9`,
    `src/__tests__/tauriSecurity.test.ts:6-7`).
  - Importing `typescript` in a Vitest file.
