# Story 006: On the project page, the ready popover comes in front of the warning card, as a live copy whose scan bar sweeps

## Symptom

In the hero of the project page, the app's ready popover is a still
screenshot, `site/img/ready.png`, and it sits behind the warning card. `.shots`
(`site/index.html:149-152`) lists it first and `site/img/warning.png` last, so
where the two overlap the warning card is painted over it. The human asked for
the ready popover "on the first layer" and "animated like now it is". That
means in front of the warning card, and no longer a picture of the app: a
live HTML/CSS copy of the app's ready view, its orange scan bar sweeping up
and down as it does in the app.

## Evidence

I read the code at `origin/epic/site` (47a014b, the same commit as
`origin/develop`). Nothing was built, run or measured. Every line number in the
request is still correct.

  comes first, with alt "The QR Scanner popover, ready to scan". warning.png
  comes last, with alt "A scanned link with two warnings: not encrypted, and a
  link shortener".

### Notes on the instrument (read from the installed sources, not run)

- vitest runs `src/**/*.test.{ts,tsx}` in jsdom (`vite.config.ts:13-16`).
  `tsconfig.json` lists `vite/client` in its types, and that declares `*?raw`
  modules as strings. Vite 8.3.5 answers a `?raw` import by reading the file as
  UTF-8 and exporting the text. So a test in `src/__tests__/` can load the page
  like this:

  ```ts
  import html from "../../site/index.html?raw";
  const page = new DOMParser().parseFromString(html, "text/html");
  ```

- **Trap: `DOMParser` documents have no style sheets in jsdom.** In jsdom
  30.1.3, a `<style>` element builds its sheet only when its document has a
  window: `HTMLStyleElementImpl._updateAStyleBlock` returns early when
  `_defaultView` is null, and a `DOMParser` document has none. So
  `page.styleSheets` is empty and `style.sheet` is null. To read the rules
  through the CSSOM, copy the style text into a `<style>` appended to the
  test's own `document`, or parse the text. Either is fine.
- **Trap: `order` matches `border`.** A plain text search for `order` hits the
  six `border` declarations listed above.
- **Trap: pseudo-element selectors.** The app's reduced-motion selector,
  `*, *::before, *::after`, has pseudo-element parts. Under the matching rule
  defined below, those parts never match, and the `*` part does.

### Which card covers which (coordinator's choice, under the human's delegation)

Putting the popover in front changes how much of the warning card the hero
shows. These numbers are estimated from `site/index.html:82-85` and the
screenshots' proportions, ignoring the tilts; they were not measured. Call the
width of `.shots` W:

- The popover covers x 0 to 0.72W, and y 0 to about 0.68W if the copy keeps the
  screenshot's proportions.
- The warning card covers x 0.28W to W, and y 0.22W to 0.95W.

With the popover in front, it hides roughly the left 61% of the top 63% of the
warning card. In `site/img/warning.png` that region holds the card's title, most
of its label "▲ LINK - CHECK BEFORE OPENING", the headline bit.ly, the URL and
the left part of the first warning. The × button, "Scan again", the second
warning and the Copy / Open anyway buttons stay visible. Today it is the other
way round: the warning card hides the right part of the ready popover's lower
half (the Scan button and the hint), and the scan bar's path is mostly in the
part that stays visible.

Hiding the warning card's label, headline and URL would leave it showing
nothing worth showing. So the two swap sides, and keep the places, tilts and
offset of today's layout: the warning card is held left and higher, turned
-3deg, and the popover is held right and 22% lower, turned 4deg, in front.
The popover then covers the warning card's lower right (part of the second
warning and the Copy / Open anyway buttons), and the label, bit.ly and the URL
stay in view. AC4 pins this.

## Acceptance criteria

The instrument is one new test file in `src/__tests__/`. These terms are used
throughout:

- **The page** is `site/index.html`, imported as text and parsed with
  `DOMParser`.
- **The popover** is the last element child of the page's `.shots`. **The
  warning image** is its first element child. **The scan bar** is the element
  with class `scanline` inside the popover.
- **The rules** are the style rules of the page's one `<style>` element
  (`site/index.html:22-124` today), including the style rules nested in its
  `@media` blocks.
- A rule **matches** an element when `Element.matches` is true for at least
  one of the comma-separated parts of its selector. A part with a
  pseudo-element never matches.
- A rule **declares** a property when its own declaration block sets it,
  whether or not another rule overrides it (see Known weakness).
- A rule **hides** an element when it matches it and declares
  `display: none`, `display: contents`, `visibility: hidden` or `opacity: 0`.

**AC1 — In `.shots` the warning image comes first and the live popover last, the page no longer refers to ready.png, and no rule or inline style reorders their painting.**
Instrument: the new test asserts, on the page:

- (a) `.shots` has exactly two element children.
  - The first is an `<img>` whose `src` attribute is img/warning.png and whose
    `alt` is "A scanned link with two warnings: not encrypted, and a link
    shortener".
  - The last is not an `img`, `picture`, `svg`, `canvas`, `object`, `embed` or
    `iframe` element, and its `role` attribute is `img`.
- (b) The text of `site/index.html` does not contain `ready.png`.
- (c) No rule, inside or outside `@media`, declares `z-index` or `order`.
  Neither `.shots` nor an element inside it has a `style` attribute.

Why (c) is enough: both children carry a transform (AC4), so each is a stacking
context at `z-index: auto`. CSS paints such siblings in document order, and for
grid items in order-modified document order, which only `order` changes.

Goes red when, in `site/index.html`:
- the popover is placed before the warning image (the base's order);
- the ready `<img>` is kept as a third child;
- ready.png is used as a background image inside the copy;
- `z-index: 1` is added to the `.shots img` rule;
- `order: -1` is added to a rule that matches the popover;
- the popover gets `style="z-index: -1"`.

**AC2 — The popover is one picture named by the old alt text, its parts hidden from assistive technology, nothing in it focusable, and the app's words in it as text.**
Instrument: the new test asserts, of the popover:

- (a) Its `role` is `img`, and its `aria-label` is exactly "The QR Scanner
  popover, ready to scan". It has no `aria-hidden` attribute.
- (b) Each of its element children has `aria-hidden="true"`, and it has no
  direct text node other than whitespace.
- (c) Neither it nor one of its descendants is an `a`, `area`, `button`,
  `input`, `select`, `textarea`, `summary`, `iframe`, `object`, `embed`,
  `audio` or `video` element, or has a `tabindex`, `href` or `contenteditable`
  attribute.
- (d) Its `textContent` is lowercased, with runs of whitespace collapsed to one
  space. It contains each of these five strings: "qr scanner", "⇧⌘2", "drag a
  box around", "any code on screen", "photo, pdf, paused video, web page. esc
  cancels.". And one of its descendants has a trimmed, lowercased
  `textContent` of exactly "scan".

Goes red when, in `site/index.html`:
- the Scan button is drawn with a `<button>`;
- the chip is a `<button>`;
- `tabindex="0"` is put on the popover;
- `aria-hidden` is removed from one child of the popover;
- `role="img"` or the label text is changed;
- the hint sentence is left out;
- the popover is replaced by an `<img>` of the same picture.

**AC3 — The scan bar sweeps with the app's animation, nothing else on the page animates or transitions, and the reduced-motion block stops the sweep.**
Instrument: the new test asserts, using the rules:

- (a) The popover holds exactly one element with class `scanline`, the scan
  bar.
  - A rule outside `@media` that matches the scan bar declares the animation
    name `sweep`, the duration `2.8s`, the timing function `ease-in-out` and
    the iteration count `infinite`. These may be given as the shorthand, in any
    order, or as longhands (`src/styles.css:245`).
  - A rule that matches the scan bar declares `position: absolute`.
  - A rule that matches its parent element declares `position: relative`
    (`src/styles.css:187-189`, `src/styles.css:238-246`).
  - No rule hides the scan bar.
- (b) An `@keyframes sweep` rule sets `top: 10%` at `0%` and at `100%`, and
  `top: 78%` at `50%` (`src/styles.css:438-446`).
- (c) Only the scan bar moves:
  - `sweep` is the only `@keyframes` rule.
  - Each rule that declares `animation` or `animation-name` with a value other
    than `none` matches the scan bar.
  - No rule declares `transition` or a `transition-` longhand.
- (d) Inside an `@media` rule whose condition is
  `(prefers-reduced-motion: reduce)`, a rule that matches the scan bar declares
  `animation: none` or `animation-name: none` with `!important`, as the app
  does (`src/styles.css:459-465`). Then no order or specificity of the rule in
  (a) can win over it.

Goes red when, in `site/index.html`:
- the duration becomes `3s`;
- the 50% keyframe says `80%`;
- the scan bar's animation is removed;
- the app's `rise` keyframes are copied in and the popover rises on load;
- `transition: transform 0.2s` is added to `.button.primary`;
- the reduced-motion rule for the scan bar is removed, loses its `!important`,
  or is moved out of the `@media` block;
- `position: absolute` is dropped from the scan bar, or `position: relative`
  from its parent;
- the scan bar gets `display: none`.

**AC4 — The two pictures share one grid cell at 72% of its width: the warning image held left and tilted -3deg, the popover held right, 22% lower and tilted 4deg.**
Instrument: the new test asserts, using the rules. The positive checks
("declares") look only at rules outside `@media`. The negative checks ("no
rule") look at the rules inside and outside `@media`.

- (a) A rule that matches `.shots` declares `display: grid`.
- (b) For each of the popover and the warning image:
  - a rule that matches it declares `grid-area: 1 / 1`;
  - a rule that matches it declares `width: 72%`;
  - no rule that matches it declares `position: absolute` or
    `position: fixed`, or a `width`, `min-width`, `inline-size` or
    `min-inline-size` in `px`;
  - no rule hides it.
- (c) Rules that match the warning image declare `justify-self: start` and
  `transform: rotate(-3deg)`, and no rule that matches it declares a
  `margin-top` other than `0`. Rules that match the popover declare
  `justify-self: end`, `margin-top: 22%`, `transform: rotate(4deg)` and
  `overflow: hidden`. These are the places, tilts and offset of
  `site/index.html:82-85` today, with the two pictures swapped.

Goes red when, in `site/index.html`:
- the popover gets `width: 354px`, the app's sheet width;
- the popover gets `position: absolute`;
- the `grid-area` rule still matches only `img`, so the popover falls into a
  second row below the warning;
- the popover's `rotate(4deg)` is dropped;
- the popover's `margin-top: 22%` is dropped;
- `margin-top: 22%` is declared by a rule that also matches the warning image
  (for example `.shots img`), so both are lowered;
- the sides are not swapped (the popover held at `start`);
- `overflow: hidden` is dropped from the popover;
- `.shots` loses `display: grid`;
- the warning image gets `display: none`.

## Known weakness of the instrument

- **jsdom does no layout, paint or animation.** Nothing here sees the popover in
  front, the bar moving, the look, or the page at 375px:
  - **"In front" is inferred, not seen.** Both children carry a transform
    (AC4), and nothing declares `z-index` or `order` (AC1). The criteria rely
    on CSS then painting the children in document order: CSS 2.1's painting
    order (Appendix E), with grid items painted in order-modified document
    order. A 3D rendering context would reorder them, for example
    `transform-style: preserve-3d` on `.shots` with a `translateZ` on a child.
    Nothing checks for that.
  - **"Declares" is not "wins".** The test does not resolve the cascade. A
    later or more specific rule that overrides a declaration AC3(a) or AC4 asks
    for still passes. Examples: a second rule setting `transform: none` on the
    popover (which would also put the warning card back in front), or one
    setting `width: auto`. Only the reduced-motion rule is protected, by the
    `!important` that AC3(d) requires.
  - **The sweep is checked as declarations:** name, duration, timing, iteration
    count and keyframes. Only a person can see that the bar moves, stays inside
    the viewfinder, multiplies over the halftone and passes behind the prompt.
  - **Reduced motion:** the test proves the rule sits inside the media block.
    It does not prove that a browser with Reduce motion turned on applies it.
  - **Phone width.** AC4 pins the properties that kept the screenshots inside
    the column: one grid cell, a percentage width, no width in `px`, no
    absolute positioning. It also pins the popover's `overflow: hidden`. At
    375px the column is about 327px (the `.wrap` padding,
    `site/index.html:59`), so the popover is about 235px wide, against the
    app's 354px sheet. Its text can be cramped, or clipped by the
    `overflow: hidden`. Clipping does not scroll the page, but only a person
    sees it.
  - **The look:** no criterion compares colours, fonts, sizes, the halftone,
    the corners or the shadows with the app.
- **AC2 checks attributes and element names, not a screen reader.** Only a
  person can check that VoiceOver reads one image named by the label. AC2 does
  not check the cursor.
- **On the base.** AC1 fails on the base because of the order of `.shots`.
  AC2, AC3 and AC4 fail on the base only because the popover does not exist
  there; their value is in the mutations they name.
- **Two dependencies were read, not run:** Vite 8.3.5's `?raw` loading and
  jsdom 30.1.3's rule that a style sheet needs a window. I did not check
  whether jsdom's CSSOM keeps every declaration the test needs as written, for
  example how it serialises the `animation` shorthand. If it does not, the
  test may read the style text instead; either way satisfies the criteria.
- **Not covered:** the Open Graph and Twitter tags at `site/index.html:12-20`.
  Nothing checks that they stay as they are.
