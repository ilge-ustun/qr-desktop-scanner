# Story 021: the popover shows over an app that is in full screen

## Symptom

The human's report (22 Oct 2026, v0.2.0 on a Mac): "when in full screen, the
app window is not visible, it's behind the full screen window."

Another app is in full screen, in its own Space. The user clicks the QR icon
in the menu bar: the popover does not show over that app. The user scans with
the hotkey: when the scan ends, the popover with the result does not show over
that app.

Read on epic/fullscreen at 8b4ae11, which is also the tip of develop. Nothing
was built, run or measured. What the code does now:

- The popover is the one window, `"main"` (`src-tauri/tauri.conf.json:15`),
  with `"alwaysOnTop": true` (`src-tauri/tauri.conf.json:21`) and
  `"visibleOnAllWorkspaces": true` (`src-tauri/tauri.conf.json:24`).
- `setup` makes the app an accessory app (no Dock icon)
  (`src-tauri/src/lib.rs:52-54`), then shows the popover once
  (`src-tauri/src/lib.rs:60`).
- `popover::show` places the window, shows it and focuses it
  (`src-tauri/src/popover.rs:37-42`). A left click on the tray icon calls it
  through `popover::toggle` (`src-tauri/src/tray.rs:47-56`).
- At the end of a scan, `popover::show` runs again unless the user cancelled
  (`src-tauri/src/scan.rs:47-49`, `core/src/scan.rs:39-41`).
- No code in the app sets the window's collection behavior or its level.
  The only settings are the two config keys above.

## Evidence

1. **The report's two paths are one path.** The hotkey does not open the
   popover itself. It starts a scan (`src-tauri/src/lib.rs:18-22`). The scan
   hides the popover (`src-tauri/src/scan.rs:68`), and at the end shows it
   again (`src-tauri/src/scan.rs:47-49`). The tray menu's Scan and Find All
   items do the same (`src-tauri/src/tray.rs:41-43`). So each case in the
   report ends in `popover::show` (`src-tauri/src/popover.rs:37-42`). This
   story changes the window once, before any of them.

2. **The cause, as the code shows it: confirmed.** Tauri makes the window
   with tao 0.37.1 (Cargo.lock). In tao 0.37.1's macOS `window.rs` (in the
   cargo registry):
   - `set_visible_on_all_workspaces` (lines 1537-1546) reads
     `collectionBehavior`, adds `CanJoinAllSpaces` only, and writes it back.
     tao calls it when it makes the window (line 623).
   - `alwaysOnTop` sets `NSFloatingWindowLevel` when tao makes the window
     (lines 288-290), and `set_always_on_top` sets the same level (lines
     1389-1396).

   No other code writes `collectionBehavior`. A search for
   `collectionBehavior`, `setCollectionBehavior` and `FullScreenAuxiliary`
   found only those lines of tao. The search covered tauri 2.12.5,
   tauri-runtime-wry 2.12.3, wry 0.57.0, tray-icon 0.25.1,
   tauri-plugin-positioner 2.4.0, `src-tauri/` and `core/`. So the window
   has no `FullScreenAuxiliary`. That flag lets the window show in another
   app's full-screen Space. That this flag is the cure is a claim about
   AppKit. Nobody observed it for this story (Known weakness).

3. **The bit values and AppKit's rules.** objc2-app-kit 0.3.2's generated
   `NSWindow.rs` (in the cargo registry) defines
   `NSWindowCollectionBehavior` over `NSUInteger` (lines 145-182):
   `CanJoinAllSpaces = 1<<0`, `MoveToActiveSpace = 1<<1`,
   `FullScreenPrimary = 1<<7`, `FullScreenAuxiliary = 1<<8`,
   `FullScreenNone = 1<<9`. Its doc comment says "You may specify at most one
   of `FullScreenPrimary`, `FullScreenAuxiliary`, or `FullScreenNone`"
   (lines 127-129). The coordinator says also that AppKit does not accept
   `CanJoinAllSpaces` together with `MoveToActiveSpace`. That file does not
   say so, and it is not checked here. Clearing `MoveToActiveSpace` is safe
   in either case, because a window that is on all Spaces does not need it.
   `NSUInteger` is `usize`, which is 64 bits on every Mac this app supports.
   So a `u64` holds each bit.

4. **The window exists when `setup` runs, on the main thread.** In tauri
   2.12.5's `app.rs` (in the cargo registry), `setup` first builds each
   window in the config, and then calls the app's setup closure (lines
   2688-2702). On the main thread, tauri-runtime-wry 2.12.3 handles window
   creation immediately, not later (`lib.rs` lines 263-280). So when the
   closure at `src-tauri/src/lib.rs:46` runs, the `"main"` NSWindow exists
   and already has tao's `CanJoinAllSpaces`. Tauri calls `setup` from the
   event loop's Ready event (`app.rs` lines 1442-1447). Tauri's own code
   later in the same Ready path takes a `MainThreadMarker` with
   `new_unchecked` (`app.rs` line 2741). `WebviewWindow::ns_window()`
   gives the NSWindow as a `*mut c_void` (tauri 2.12.5, the `mod.rs` of its
   window module, lines 1729-1745).

5. **The dependencies are already locked.** Cargo.lock has objc2 0.6.5
   (`Cargo.lock:2423-2430`) and objc2-app-kit 0.3.2
   (`Cargo.lock:2433-2445`). Tauri 2.12.5 depends on objc2-app-kit 0.3.2,
   with its `NSWindow` feature, on macOS. The shell's entry lists neither
   (`Cargo.lock:2968-2981`). A macOS-only dependency on them changes that
   entry's `dependencies` list and adds no `[[package]]`. The fleet runs
   `cargo test --locked` (`.fleet/config:34`), so the builder commits
   Cargo.lock with the change. The vitest test that reads Cargo.lock checks
   only qr-core and rxing (`src/__tests__/coreDependencies.test.ts:59-74`).

6. **What checks the shell.** `scripts/check-macos-shell.sh` lints the shell
   for `aarch64-apple-darwin` (`scripts/check-macos-shell.sh:22`,
   `scripts/check-macos-shell.sh:39-40`): it type-checks macos.rs, and runs
   and links nothing. For that target `platform.rs` takes macos.rs, not
   unsupported.rs (`src-tauri/src/platform.rs:6-14`). So nothing here or in
   CI compiles unsupported.rs. macOS CI runs on a push to main or develop and
   on a pull request (`.github/workflows/macos.yml:11-18`), not on a push to
   epic/fullscreen or story/021.

7. **The coordinator's decisions (delegated by the human, 22 Oct 2026).**
   The bit rule goes in qr-core, in a new module, where a cargo test reaches
   it. The shell applies it once, in `setup`, before the first
   `popover::show`. The window level stays as it is (floating, from
   `alwaysOnTop`). The flag is the missing part. A higher level can be a
   later story if the Mac shows that one is necessary.

8. **Naming the evidence.** A unit test in core/src is
   `cargo:qr-core/lib::window::tests::<name>`. A test in a new file in
   core/tests is `cargo:qr-core/<file stem>::<name>`
   (`.fleet/rules.md:16-18`). The reviewer's probes are integration tests in
   core/tests that call the public paths below.

## Acceptance criteria

The ACs name one public function and five public constants, in a new module
core/src/window.rs, declared `pub mod window;` in `core/src/lib.rs`. Their
names, paths and types are fixed, so that a probe in core/tests can use them:

- `qr_core::window::popover_collection_behavior(current: u64) -> u64`: takes
  the window's `collectionBehavior` as raw bits and returns the bits that the
  popover needs.
- `qr_core::window::CAN_JOIN_ALL_SPACES: u64 = 1 << 0`,
  `MOVE_TO_ACTIVE_SPACE: u64 = 1 << 1`, `FULL_SCREEN_PRIMARY: u64 = 1 << 7`,
  `FULL_SCREEN_AUXILIARY: u64 = 1 << 8`, `FULL_SCREEN_NONE: u64 = 1 << 9`.
  The doc comment of each gives AppKit's full name, for example
  `NSWindowCollectionBehaviorFullScreenAuxiliary`.

The module has no `cfg(target_os)`, and qr-core gets no new dependency.

Each instrument is a Rust test in qr-core: in a `tests` module in
core/src/window.rs, or in a new file in core/tests. It compares the function's
result with `assert_eq!` against the **literal** numbers in the tables below.
It does not compare against the constants, because a wrong constant would then
pass. On today's tree each test fails to compile, because the module does not
exist.

**AC1 — `popover_collection_behavior` sets CanJoinAllSpaces (bit 0) and FullScreenAuxiliary (bit 8), and clears MoveToActiveSpace (bit 1), FullScreenPrimary (bit 7) and FullScreenNone (bit 9).**

| current | result |
|---|---|
| `0x0` | `0x101` |
| `0x1` | `0x101` |
| `0x2` | `0x101` |
| `0x3` | `0x101` |
| `0x80` | `0x101` |
| `0x81` | `0x101` |
| `0x100` | `0x101` |
| `0x101` | `0x101` |
| `0x200` | `0x101` |
| `0x301` | `0x101` |
| `0x383` | `0x101` |

Row 2 (`0x1`) is what tao leaves on the window if AppKit's starting value is
0. That starting value was not observed.

Instrument: a test of `qr_core::window::popover_collection_behavior` with
these eleven rows.
Goes red when core/src/window.rs does not set bit 8 (row 2 gives `0x1`, which
is today's window); has `FULL_SCREEN_AUXILIARY` as `1 << 7` (row 1 gives
`0x81`); does not set bit 0 (row 1 gives `0x100`); does not clear bit 1 (row
3 gives `0x103`), bit 7 (row 5 gives `0x181`) or bit 9 (row 9 gives
`0x301`); toggles bit 8 with `^` and does not set it (row 7 gives `0x1`); or
sets the two bits first and then clears a mask that has bit 8 in it (row 1
gives `0x1`).

**AC2 — paired with AC1: each of the 59 bits of a `u64` other than bits 0, 1, 7, 8 and 9 comes out as it went in.**

The rows:

- one row for each bit `i` in `0..64`, except 0, 1, 7, 8 and 9: current
  `1 << i`, result `(1 << i) | 0x101`. Three examples: `1 << 10` gives
  `0x501`; `1 << 12` (FullScreenDisallowsTiling) gives `0x1101`; `1 << 63`
  gives `0x8000_0000_0000_0101`;
- current `u64::MAX`, result `0xFFFF_FFFF_FFFF_FD7D`;
- current `0x1286` (Managed, MoveToActiveSpace, FullScreenPrimary,
  FullScreenNone, FullScreenDisallowsTiling), result `0x1105`.

Instrument: a test of `qr_core::window::popover_collection_behavior` with
these 61 rows.
Goes red when core/src/window.rs returns `0x101` whatever the input is (each
single-bit row); keeps only the low 32 bits, for example through a `u32`
(the rows for bits 32 to 63, and `u64::MAX`); clears the full-screen tiling
bits 11 and 12 or the bits 16 to 18 too (their single-bit rows); or clears
bits 0 to 9 as a block and then sets the two bits (the rows for bits 2 to 6,
and row `0x1286` gives `0x1101`).

**Also required, in the shell.** These are not ACs, because no test here runs
the shell. `scripts/check-macos-shell.sh` compiles and lints it as macOS
compiles it, in the baseline, and a red result vetoes. The reviewer reads the
rest in the diff.

1. **macos.rs applies the rule to an NSWindow.** One new public function in
   `src-tauri/src/platform/macos.rs` takes the popover window. It gets the
   NSWindow from `ns_window()`, reads `collectionBehavior`, passes its bits
   through `qr_core::window::popover_collection_behavior`, and sets the
   result with `setCollectionBehavior`. The shell holds no bit rule of its
   own: no collection-behavior flag is named, added or removed in the shell.
   If `ns_window()` gives an error, the function does nothing: no `unwrap`,
   no `expect`, no panic. The app then starts as it does today. Each
   `unsafe` block has a `// SAFETY:` comment, as the file has now
   (`src-tauri/src/platform/macos.rs:23`).
2. **The stub matches.** `src-tauri/src/platform/unsupported.rs` gets a
   function with the same name and signature that does nothing.
3. **Once, before the first show.** The `setup` closure in
   `src-tauri/src/lib.rs` calls the platform function with the `"main"`
   window before `popover::show` (`src-tauri/src/lib.rs:60`). No other place
   calls it. The window level does not change: nothing calls `setLevel` or
   `set_always_on_top`, and tauri.conf.json is not changed (it is denied).
4. **Only locked versions.** objc2-app-kit (and objc2, if the code uses it)
   goes in `src-tauri/Cargo.toml` under
   `[target.'cfg(target_os = "macos")'.dependencies]`, with version
   requirements that 0.3.2 and 0.6.5 meet, and the features the code uses.
   In Cargo.lock, only the `dependencies` list of `qr-desktop-scanner`
   changes. No `[[package]]` is added, removed or changed.

## Known weakness of the instrument

- **AC1 and AC2 prove only the bit arithmetic.** Nothing here runs AppKit.
  That `FullScreenAuxiliary` lets an accessory app's window show in another
  app's full-screen Space is a claim about AppKit. Nobody observed it for
  this story. Only a person on a Mac sees whether the popover now shows over
  a full-screen app (Human verification).
- **No instrument sees the shell call the function.** A builder who adds
  core/src/window.rs and does not change the shell passes AC1 and AC2. Items
  1 to 4 of "Also required" are checked by reading the diff, by
  `scripts/check-macos-shell.sh` (which compiles and lints, and runs
  nothing), by macOS CI, and by a person on a Mac.
- **macOS CI does not build this story's branch on a push** (Evidence 6).
  The first real macOS build and link of this change is the coordinator's
  manual macOS CI run (workflow_dispatch) on epic/fullscreen's tip, before
  the epic lands.
- **The stub is compiled nowhere** (Evidence 6). Only `cargo fmt` parses
  unsupported.rs. A wrong signature there shows only in a Linux build of the
  shell, which this box cannot do.
- **The window level stays floating** (Evidence 7). If, on the Mac, the
  popover is in the full-screen Space but under the full-screen app's
  window, the level is the next thing to change, in a later story.
- **Which value AppKit starts with, and that nothing writes it later, was
  read, not observed.** Evidence 2 and 4 come from reading the dependencies'
  source. If something at run time writes `collectionBehavior` after
  `setup`, the flag can go, and nothing here would see that.
- **The `MoveToActiveSpace` rule is not checked** (Evidence 3). The function
  clears that bit in any case.
- **The main thread.** `setup` running on the main thread is read from
  Tauri's source (Evidence 4), not observed. An NSWindow call off the main
  thread can crash the app, and only a run on a Mac would show it.
- **Focus in a full-screen Space is not observed.** The popover hides when it
  loses focus (`src-tauri/src/popover.rs:75-84`). That it gets focus in
  another app's full-screen Space, and hides on a click elsewhere there, is
  for the person on the Mac to see.

## Human verification

On a Mac, with `npm run tauri dev` from story/021's tree, or with the .app
from the coordinator's macOS CI run on epic/fullscreen's tip. Put an app
in full screen (Safari: View > Enter Full Screen, or ⌃⌘F) for each of the
first four items.

- [ ] In the full-screen app, move the pointer to the top of the screen so
      that the menu bar shows. Click the QR icon. The popover shows over the
      full-screen app, under the icon. The Mac stays in that Space.
- [ ] Click in the full-screen app. The popover hides.
- [ ] In the full-screen app, press the hotkey and drag a box around a QR
      code. The popover with the result shows over the full-screen app.
- [ ] In the full-screen app, choose Find All Codes on Screen from the tray
      menu (right click). The popover with the results shows over the
      full-screen app.
- [ ] Press the hotkey and press Esc. No popover shows, as before.
- [ ] With no app in full screen: click the icon. The popover shows under it
      and over the other windows, as before. Go to a second desktop Space
      (⌃→) and click the icon there. The popover shows on that Space, and the
      Mac does not go back to the first one.
- [ ] Quit and start the app again while an app is in full screen. The
      popover that opens at launch shows (on the Space that is active), and
      the app does not crash.
