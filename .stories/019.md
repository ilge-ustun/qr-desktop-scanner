# Story 019: one scan pipeline in qr-core with typed errors, and the shell's scan logic moved into core

## Symptom

Read on epic/core at 60fb392, after story 018 merged. The scan flow has three
problems. Story 018 did not change them.

**1. run_scan and run_find_all repeat each other.** Each one checks the
permission, sweeps, and makes the temp directory
(`core/src/scan.rs:74-81`, `core/src/scan.rs:111-118`). Each one captures,
then opens each image with the same error text (`core/src/scan.rs:93-96`,
`core/src/scan.rs:132-135`), then decodes. Only run_find_all removes a
repeated code (`core/src/scan.rs:129-139`).

**2. Errors are outcomes, and the helper that makes them is in two files.**
temp_dir returns `Result<TempDir, ScanOutcome>` (`core/src/scan.rs:177-182`).
`fn error(message: String) -> ScanOutcome` is at `core/src/scan.rs:192-194`
and at `src-tauri/src/scan.rs:92-94`. Each error text is a format string at
its call site.

**3. The shell holds scan logic that no test reaches.**
`src-tauri/src/scan.rs` creates the scratch directory
(`src-tauri/src/scan.rs:64-66`). It picks the flow from the Scope
(`src-tauri/src/scan.rs:73-86`). It decides what follows the outcome: it asks
for the permission on PermissionDenied (`src-tauri/src/scan.rs:45-47`), and
it opens the popover again unless the outcome is Cancelled
(`src-tauri/src/scan.rs:49-53`). The shell does not build on Linux
(`.fleet/rules.md:20-21`), so no test runs these lines.

## Evidence

Read only. Nothing was built, run or measured. A read-only review of develop
asked for this story. Story 018 changed these files after that review. This
is what the files hold now.

1. **Item 1 is confirmed, with one difference that the shared step must
   keep.** After the capture, run_scan treats a missing file as Esc and
   gives Cancelled (`core/src/scan.rs:89-92`; `core/tests/scan.rs:98-103`
   holds it). run_find_all skips a missing file. When no file is left, it
   gives an Error, never a cancel (`core/src/scan.rs:123-128`). So run_scan
   keeps its own Esc check after the capture, and the shared step takes
   run_find_all's rule. The pipeline is: permission, sweep, temp directory,
   capture, (run_scan only: no file gives Cancelled), shared decode step.

   The shared step removes a repeated code by its text and keeps the first,
   as run_find_all does now. `seen.insert` at `core/src/scan.rs:138` also
   removes a repeat inside one image. For run_scan this is new, but only
   for a decoder that gives the same text twice for one image. RxingDecoder
   never does that (`core/src/decode.rs:86-89`), so the app shows no change.
   AC5 uses a fake decoder to see it.
2. **Item 2 is confirmed. ScanError has five variants, not four.** qr-core
   depends on `thiserror = "2"` (`core/Cargo.toml:13`).
   `core/src/url_guard.rs:6` and `core/src/wifi.rs:4` use it. The review
   names four error kinds: the temp directory, the capture, an unreadable
   image and a missing screenshot. Item 3 moves a fifth one into core: the
   creation of the scratch directory. Its text names the path:
   `could not create {path}: {e}` (`src-tauri/src/scan.rs:65`). If that
   error becomes the temp-directory variant, the text changes to
   `could not create a temporary directory: …`. So it gets its own variant.
   A capture error has no prefix: the capturer's text is the message
   (`core/src/scan.rs:87`, `core/src/scan.rs:121`;
   `core/tests/scan.rs:105-115`).
3. **Item 3 is confirmed. Two more parts of that function stay in the
   shell:**

     runs before `scan://started` and the hide
     (`src-tauri/src/scan.rs:67-69`). When the permission is off, the
     popover stays open and the page gets no started event. Core checks
     again, as it does today.
   - `app_cache_dir()` (`src-tauri/src/scan.rs:60-63`). It is a Tauri call,
     so it stays in the shell, with its text.
4. **No wording changes.** The review says that the "no cache directory"
   text can change. It does not need to: the call that gives that error

   `could not create {path}: {e}` moves to core with the same text.

   item 3 of the coordinator's intent: "Move create_dir_all into core's
   temp-dir step". **Coordinator's choice (delegated by the human, 22 Oct

6. **Story 020 merged into epic/core after this draft was written** (PASS,

## What the ACs call

Public in qr-core, re-exported from `core/src/lib.rs` as `qr_core::run` and
`qr_core::ScanError`. The names, paths and signatures are fixed, so that a
probe in core/tests can call them.

- `pub fn run(scope: Scope, permission: &dyn ScreenPermission, area: &dyn Capturer, screen: &dyn DisplaysCapturer, decoder: &dyn Decoder, scratch: &Path) -> ScanOutcome`.
  `Scope::Area` runs run_scan with `area`. `Scope::Screen` runs run_find_all
  with `screen`.
- `ScanOutcome::asks_for_permission(&self) -> bool` and
  `ScanOutcome::reopens_popover(&self) -> bool`.
- `pub enum ScanError`, with `#[derive(Debug, thiserror::Error)]`. These are
  the five variants. Each message is today's text, from the cited line:

| variant | message | today |
|---|---|---|
| `Scratch { path: PathBuf, source: std::io::Error }` | `could not create {path.display()}: {source}` | `src-tauri/src/scan.rs:65` |
| `TempDir(std::io::Error)` | `could not create a temporary directory: {0}` | `core/src/scan.rs:181` |
| `Capture(String)` | `{0}` | `core/src/scan.rs:87`, `core/src/scan.rs:121` |
| `UnreadableImage(image::ImageError)` | `could not read the screenshot: {0}` | `core/src/scan.rs:95`, `core/src/scan.rs:134` |
| `NoScreenshot` | `no screenshot was written` | `core/src/scan.rs:127` |

- `impl From<ScanError> for ScanOutcome`, which gives
  `ScanOutcome::Error { message: err.to_string() }`.

These stay as they are: the signatures of run_scan, run_find_all and
sweep_stale (the tests that exist call them); the traits ScreenPermission,
Capturer and DisplaysCapturer; the enums Capture and Scope; and the variants

### Also required, with no instrument here

Known weakness says how these are checked.

In `core/src/scan.rs`:

- One private function opens and decodes the shots for both flows. The
  request calls it `decode_shots(&[PathBuf], &dyn Decoder)`. It skips a
  missing file. It gives NoScreenshot when no file is left. It gives
  UnreadableImage for the first image that it cannot open. It removes a

  Then it makes the `scan-` directory in scratch (the error is TempDir). It
  returns `Result<TempDir, ScanError>`.

  only through the From impl. No `fn error(` stays in the file.

  when it is missing.

In `src-tauri/src/scan.rs`:

- These stay: the SingleFlight guard (`src-tauri/src/scan.rs:35-43`), the

## Acceptance criteria

Each instrument is a test in the new file pipeline.rs in core/tests. Unless
a test says otherwise: scratch is a new `tempfile::tempdir()`; the
permission fake grants; and the area fake writes `qr("https://example.com", 8)`
to `dest` and returns `Ok(Capture::Taken)`, as `core/tests/scan.rs:19-26`
does. On today's tree the file does not compile: `run`, `ScanError` and the
two methods do not exist. Each AC also says what the test would give on
today's tree if it compiled.

**AC1 — run_scan and run_find_all create a scratch directory that is missing two levels deep, and then scan in it.**
Instrument, two tests. In each, scratch is `<tempdir>/Caches/qr`, and
neither `Caches` nor `qr` exists.
- `cargo:qr-core/pipeline::run_scan_creates_a_missing_scratch`: run_scan
  with the area fake gives `Found` with exactly one code, text
  `https://example.com`. After the call, scratch is a directory with no
  entries.
- `cargo:qr-core/pipeline::run_find_all_creates_a_missing_scratch`: the same
  with run_find_all and a DisplaysCapturer fake that writes one display,
  display-1.png, with that code and returns its path.

On today's tree each call gives
`Error { message: "could not create a temporary directory: …" }`
(`core/src/scan.rs:181`), because `tempdir_in` needs scratch to exist.
Goes red when temp_dir's `create_dir_all` is removed (both tests). Goes red
when it becomes `fs::create_dir`, because `Caches` is missing (both). Goes
red when the creation is only in run_scan (second test), or only in `run`
(both).

**AC2 — run picks the flow from the Scope: Area calls only the area capturer, Screen calls only the displays capturer, and both pass the permission on.**
Instrument, two tests. Each test makes one area fake and one displays fake.
Each fake counts its calls in a `Cell<u32>`. The area fake writes the code
`area` to `dest`. The displays fake writes one display, display-1.png, with
the code `screen`, and returns its path. Each test first calls `run` with a
permission fake that refuses, and then with one that grants.
- `cargo:qr-core/pipeline::run_area_uses_the_area_capturer_only`: with
  `Scope::Area` and the refusing permission, the outcome is
  `PermissionDenied` and both counts are 0. With the granting permission,
  the outcome is `Found` with exactly one code, text `area`. The area count
  is 1 and the displays count is 0.
- `cargo:qr-core/pipeline::run_screen_uses_the_displays_capturer_only`: the
  same with `Scope::Screen`. With the granting permission, the outcome is
  `Found` with exactly one code, text `screen`. The displays count is 1 and
  the area count is 0.

Goes red when the two arms of `run` are swapped (both tests). Goes red when
`run` always calls run_scan (second test), or always calls run_find_all
(first test). Goes red when `run` calls both flows (the other count is 1).
Goes red when `run` passes on a permission that always grants, in place of
its argument (the PermissionDenied part).

**AC3 — asks_for_permission is true only for PermissionDenied, and reopens_popover is false only for Cancelled, over the five variants of ScanOutcome.**
Instrument: `cargo:qr-core/pipeline::the_outcome_says_what_the_shell_does_next`

## Known weakness of the instrument

- **The shell's wiring has no instrument here.** These are the edits to
  `src-tauri/src/scan.rs` under "Also required". The shell does not build on
  this Linux box. `scripts/check-macos-shell.sh` compiles and lints it for
  aarch64-apple-darwin (`scripts/check-macos-shell.sh:22`), but nothing runs
  it. No test here shows that the shell calls `run` and the two methods, or
  that it keeps the order of request_permission, the result event and
  popover::show. The reviewer checks this by reading the diff. macOS CI
  builds it. A person on a Mac runs it (Human verification).
- **There is no structural check, on purpose.** A source-text test could
  show that `fn error(` and `create_dir_all` are gone from
  `src-tauri/src/scan.rs`. But vitest collects only `src/**/*.test.*`
  (`vite.config.ts:14`), and this story denies src/. Also,
  `.fleet/rules.md:19-20` says to prove Rust logic with a Rust test, not by
  reading source as text. And a rename passes a text check.
- **One shared step, or two copies, pass the same tests.** AC4 and AC5 show
  that both flows give the same texts and remove a repeated code in the same
  way. A copy of the step in each flow passes them too. The reviewer reads
  that one private function in `core/src/scan.rs` opens the images and calls
  `decode`, and that `fn error(` is gone from that file.
- **AC5 is visible only with a fake decoder.** RxingDecoder already removes a
  repeat inside one image (`core/src/decode.rs:86-89`). With the app's
  decoder, run_scan's results do not change.
- **The temp-directory failure is tested only as text.** No test makes
  `tempdir_in` fail inside a scratch that exists: a read-only scratch does
  not stop root. AC4's table holds the TempDir message. That temp_dir gives
  TempDir for this failure is read, not tested.
- **The scratch failure is tested with one cause:** a regular file in the
  path. A permission error or a full disk is not tested. The tests compute
  the io error text and the image error text themselves, on Linux. They do
  not hard-code what macOS prints.
- **The order change of Evidence 5 is not tested,** and nobody has seen it
  on a Mac.
- **Story 018's properties are held by its own tests, not by an AC here.**
  The sweep before the capture, and the removal of the scan's directory,
  are in `core/tests/scan.rs` and `core/tests/find_all.rs`. Those tests run
  in the baseline unchanged, and they are denied. No test covers a capturer
  that returns `Ok(Capture::Cancelled)` while the permission is granted.
  That was already true before this story.
