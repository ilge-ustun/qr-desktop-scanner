# Story 008: The popover's webview gets only the three Tauri permissions it uses, and its CSP names base-uri, form-action and object-src

## Symptom

The popover's capability, `src-tauri/capabilities/default.json:6`, grants
the `main` window `"core:default"` and `"clipboard-manager:allow-write-text"`.
The page uses two event commands and one clipboard command. `core:default`
grants far more.

In the installed Tauri (2.12.5, from `Cargo.lock`), `core:default` is the
`default` set of each of nine core plugins: path, event, window, webview,
app, image, resources, menu and tray. That includes:

- **image:** `new`, `from_bytes`, `from_path`, `rgba` and `size`.
  `from_path` takes any path and has no scope. It is compiled in because the
  shell enables tauri's `image-png` feature (`src-tauri/Cargo.toml:19`).
- **tray:** `new`, `set_menu`, `set_icon`, `set_tooltip` and more.
- **menu:** every menu command, `new` and `popup` included.
- **path:** `resolve_directory`, `resolve` and the other path helpers.
- **window, webview and app:** their read-only getters, plus
  `internal_toggle_maximize`, `internal_toggle_devtools`, and app's
  `register_listener` and `remove_listener`.

Say a script were running in the page. It could call `from_path` on any PNG
the user can read, then `rgba` to get its pixels. It could then send them out
through the app's own `open_link` command. That command opens any `http`,
`https` or `mailto` URL in the default browser (`src-tauri/src/commands.rs:40-46`,
`core/src/url_guard.rs:9`).

Getting a script into the page needs a separate compromise. The CSP
(`src-tauri/tauri.conf.json:30`) has no `script-src`, so `default-src 'self'`
blocks inline and eval'd script. React renders decoded text as text. So this
story narrows what such a script could do. It closes no known way in.

The same CSP names neither `base-uri` nor `form-action`. Neither falls back
to `default-src`, so both are unrestricted: injected markup could set a
`<base>` for the page's relative URLs, or submit a form to any address.

### The CSP

- Today: `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src
  'self' data:; connect-src ipc: http://ipc.localhost`
  (`src-tauri/tauri.conf.json:30`).
- `base-uri` and `form-action` do not fall back to `default-src`. The page
  has no `<base>`, `<form>`, `<object>`, `<embed>` or `<iframe>`. I grepped
  `src/` (tests excluded) and `index.html`. `'none'` for both should
  therefore change nothing the page does (not observed).
- **`object-src`: I chose to name it, as `'none'`.** `object-src` does fall
  back to `default-src`, so today it is `'self'`. That is narrow already.
  WKWebView runs no plugins, so the gain in today's browser is small. Two
  reasons to name it anyway. First, `'none'` is narrower than `'self'` and
  costs nothing, since the page embeds nothing. Second, it no longer rides on
  `default-src`, so a later edit that widens `default-src` does not quietly
  widen `object-src`.
- How Tauri reads the string
  (`/home/fleet/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-utils-2.10.2/src/config.rs:2580-2596`):
  it splits on `;`, trims each piece, and splits on single spaces. The first
  token is the directive name. Pieces go into a map, so a later duplicate
  replaces an earlier one. A browser keeps the first. At run time Tauri adds
  hashes and nonces to `script-src` and `style-src` only
  (`/home/fleet/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/tauri-2.12.5/src/manager/mod.rs:53-107`).
  The other directives are passed through.

## Acceptance criteria

The instrument for the three criteria is one new vitest file under
`src/__tests__/`. It must be a `.ts` file: `src/__tests__/*.tsx` is denied.

**AC1 — The popover's capability grants exactly `core:event:allow-listen`, `core:event:allow-unlisten` and `clipboard-manager:allow-write-text`, to the `main` window and nothing else.**
Instrument: the test reads `src-tauri/capabilities/default.json` and parses
it as JSON.
(a) `permissions`, sorted, deep-equals
`["clipboard-manager:allow-write-text", "core:event:allow-listen", "core:event:allow-unlisten"]`.
So each of its entries is a plain string, none repeats, and there are no
others.
(b) `windows` deep-equals `["main"]`.
(c) The object's keys are exactly `$schema`, `identifier`, `description`,
`windows` and `permissions`. There is no `remote`, `webviews`, `platforms`
or `local`.
Fails on the base: `permissions` is
`["core:default", "clipboard-manager:allow-write-text"]`.
Goes red when:
- `"core:default"` is put back;
- `"core:image:default"` or `"core:image:allow-from-path"` is added;
- `"core:event:allow-unlisten"` is dropped;
- the two event entries are replaced by `"core:event:default"`, which also
  grants `emit` and `emit_to`;
- `"clipboard-manager:allow-write-text"` is dropped;
- `"windows"` becomes `["*"]`;
- a `"remote": { "urls": ["https://*"] }` key is added.

**AC2 — The CSP in `src-tauri/tauri.conf.json` keeps its four directives word for word, adds `base-uri 'none'`, `form-action 'none'` and `object-src 'none'`, and names no other directive.**
Instrument: the test reads `src-tauri/tauri.conf.json` and parses it as
JSON. `app.security.csp` is a string, as it is now. The test parses it as
tauri-utils does: split on `;`, trim each piece, drop pieces that are empty
after trimming, then split each piece on single spaces. The first token is
the directive name, and the rest are its sources, in order.
(a) No directive name appears twice.
(b) The directive names are exactly these seven: `default-src`,
`style-src`, `img-src`, `connect-src`, `base-uri`, `form-action` and
`object-src`.
(c) Each directive's sources deep-equal these, in order:
- `default-src`: `'self'`
- `style-src`: `'self' 'unsafe-inline'`
- `img-src`: `'self' data:`
- `connect-src`: `ipc: http://ipc.localhost`
- `base-uri`: `'none'`
- `form-action`: `'none'`
- `object-src`: `'none'`

Fails on the base: `base-uri`, `form-action` and `object-src` are absent.
Goes red when:
- `base-uri 'none'` is dropped;
- `form-action 'none'` becomes `form-action 'self'`;
- `object-src 'none'` is dropped;
- `style-src` loses `'unsafe-inline'`;
- `connect-src` loses `http://ipc.localhost`;
- `script-src 'self' 'unsafe-eval'` is added;
- a second `base-uri *` is appended after the first;
- the policy is rewritten in Tauri's object (directive-map) form.

**AC3 — Paired with AC1 and AC2: the capability file and the `csp` string are the only places the config grants permissions or sets a policy.**
Instrument: the same test.
(a) The files under `src-tauri/capabilities/`, at any depth, are exactly
`default.json`. List them with `import.meta.glob`, matching basenames.
(b) `app.security` in `src-tauri/tauri.conf.json` has exactly one key,
`csp`.
This is a guard: it passes on the base, and its value is in its reds.
Goes red when:
- a new file `extra.json` in `src-tauri/capabilities/` grants
  `"core:default"` to `main`. Tauri loads each file there; see Evidence;
- `app.security` gets `"capabilities": [{ "identifier": "extra", "windows": ["main"], "permissions": ["core:default"] }]`;
- `app.security` gets `"devCsp": "default-src *"`, which Tauri uses instead
  of `csp` in dev builds.

## Known weakness of the instrument

- **Config, not run time.** The test reads two JSON files. It does not show
  that Tauri enforces them, or that three permissions are enough. A missing
  permission shows only at run time on a Mac: the page's `invoke` or
  `listen` rejects. macOS CI builds the app (`.github/workflows/macos.yml:35`)
  but never runs it. That three are enough rests on reading `src/` and the
  `@tauri-apps` packages (Evidence), not on a run.
- **Identifiers checked against the test's own copy.** If an identifier were
  misspelt the same way in the JSON and in the test, vitest would pass. Only
  tauri-build rejects an unknown identifier, when the shell's build script
  runs. `scripts/check-macos-shell.sh` runs it from Linux after
  `npm run build` (`scripts/check-macos-shell.sh:12-13`), and macOS CI runs
  it. Whether the harness runs that script is not known here. I checked the
  three spellings against the crate sources (Evidence).
- **The configured CSP, not the delivered one.** The test reads the string
  in `tauri.conf.json`. The webview gets Tauri's rewrite of it. I read in
  tauri-utils and tauri that the rewrite keeps `base-uri`, `form-action` and
  `object-src`. I did not observe it. I also did not observe whether
  WKWebView enforces them.
- **No behaviour is shown to change.** That the added directives break
  nothing rests on the grep in Evidence: no `<base>`, `<form>`, `<object>` or
  `<embed>` in the page. That grep is not a test.
- **Other config sources are closed by scope_deny, not by the test.** These
  are a platform config (`tauri.macos.conf.json` and the rest), a CSP
  `<meta>` in `index.html`, a capability added from Rust at run time, and an
  app manifest in `build.rs`. Each would be a change to a denied file. The
  test does not look for them.
- **Hidden files.** `import.meta.glob` may skip dotfiles under
  `src-tauri/capabilities/` (not observed). Tauri's own glob might load one.
  The reviewer lists that directory in the diff.
- **The attack was read, not run.** The `from_path` → `rgba` → `open_link`
  path is read from the code. Nobody exercised it before or after.
- **What stays open.** The app's own commands are still outside the ACL.
  A script in the page could still call each command in
  `src-tauri/src/lib.rs:31-44`. That includes `open_link` with any `https`
  URL, `join_wifi` and `set_hotkey`. Bringing them under the ACL needs an app
  manifest in `src-tauri/build.rs`, which is out of scope. This story removes
  the core plugin commands: file reads through `image`, tray and menu
  changes, path lookups and the window, webview and app getters.
