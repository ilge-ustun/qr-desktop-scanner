# Story 017: styles.css takes its raw values from :root tokens, and App.tsx keeps its side effects in five named hooks

## Symptom

The popover's stylesheet repeats values. App.tsx mixes concerns. Both were
read on epic/quality at efdac6e, after stories 013 and 014.

**`src/styles.css`.** Outside `:root`, three declarations write a colour as a
raw value, not as a token:

- `button.risky` writes `rgba(255, 116, 119, 0.25)` (`src/styles.css:115`).
- `button.hotkey:hover` writes `rgba(255, 116, 119, 0.2)` (`src/styles.css:198`).
- `.tone-warn .meta` writes the lighter orange `#ff9496` in its stripes
  (`src/styles.css:330`).

The disabled opacity `0.55` is written two times: in `button:disabled`
(`src/styles.css:86`) and in `.keyed > button:disabled + .keycap`
(`src/styles.css:172`).

`.secret` (`src/styles.css:380`) and `.field` (`src/styles.css:404`) write the same
five declarations: `display: flex`, `align-items: center`,
`justify-content: space-between`, `gap: 10px`,
`border-top: 2px dotted var(--ink)`. Only the padding is different: `.secret`
has `padding-top: 10px` (`src/styles.css:386`), `.field` has `padding: 8px 0`
(`src/styles.css:410`).

**`src/App.tsx`.** The viewfinder has the class `tone-ok` (`src/App.tsx:92`). No
selector in styles.css uses it.

App holds the shortcut state and four effects in its own body:

- the shortcut state and its three callbacks (`src/App.tsx:15-27`), with an effect that reads getHotkey (`src/App.tsx:17`);
- an effect that sizes the window with a ResizeObserver (`src/App.tsx:31`);
- one effect (`src/App.tsx:40-61`) that does three unrelated
  things: it listens for scan events, it checks screen access, and it hides
  the popover on Esc.

`ipc.screenPermission()` has no rejection handler (`src/App.tsx:49`). If the call
rejects, the rejection is unhandled. `ipc.getHotkey()` handles its rejection:
`.then(setHotkey, () => undefined)` (`src/App.tsx:18`).

review that asked for this story read develop. What it said, and what the
files hold now:

8. **onScan also has no rejection handler** (`src/App.tsx:43-48`). The request did not ask for it. It moves as it is. This is

9. **Tokens hold literal values.** The webview target is Safari 15

**AC1 — Each of the five declarations the review found takes its value from a `:root` token, and each token's value is the old literal.**

`X` is a custom-property name the builder chooses, one per row; both opacity
rows use the same `X`. The selectors stay as written today.

| Selector | Property | Value today | Value after |
|---|---|---|---|
| `button:disabled` (`src/styles.css:84`) | `opacity` | `0.55` | `var(--X)` |
| `.keyed > button:disabled + .keycap` (`src/styles.css:171`) | `opacity` | `0.55` | `var(--X)` |

whitespace collapsed, has the form in "Value after"; (b) `--X` is declared in

## Known weakness of the instrument

- **No browser sees the CSS.** AC1 to AC3 read styles.css as text. That the
  colours, opacities and padding look the same rests on this: each token's
  value is the same text as the old literal (AC1 checks that), and the shared
  rule holds the same declarations (AC3 checks that). No test computes a
  style. jsdom resolves no `var()` and does no layout. A person on a Mac
  looks at the popover (Human verification).
- **AC2 finds hex colours and colour functions only.** A named colour
  keyword (for example `salmon`) outside `:root` is not found. AC1 pins only
  the five declarations in its table.
- **Other raw values stay.** The opacities `0.35` (`src/styles.css:179`) and
  `0.85` (`src/styles.css:505`), and the `0.18` inside `--grain`, are raw too.
  The review did not list them. No criterion covers them.
- **The CSS parse is simple.** The tests find rules by their selector text,
  with whitespace collapsed. A selector written in a different but equal form
  is not found; for that reason AC1 asks that the selectors stay as written.
- **AC5 reads names, not behaviour.** It proves that App.tsx calls five hooks
  with these names and keeps no effect code. It does not read the hooks. That
  each hook does its job is held by behaviour tests: AC6 and AC7, the Esc
  test at `src/__tests__/AppKeys.test.tsx:347`, and every test that waits for
  onScan.
- **The rejection is mocked and was never seen.** AC6 mocks ipc. The real
  rejection would come from Tauri's IPC layer; nobody has seen it. The test
  finds an unhandled rejection with its own listener on `process`, after one
  macrotask. That Node reports it within one macrotask is the documented
  behaviour, not observed here. That vitest also fails a run on an unhandled
  rejection is not observed here either, and the criterion does not rely on
  it.
- **onScan's rejection is still unhandled** (Evidence item 8). No criterion
  covers it.
- **StrictMode's double effects** in AC7 come from React's development build,
  which vitest uses. AC7 does not prove the behaviour in the production
  build, where effects run once.
- **The real window size is not tested.** AC7 sets `offsetHeight` itself and
  checks the number sent to fitPopover. That Rust resizes the window to that
  number is not tested here.
