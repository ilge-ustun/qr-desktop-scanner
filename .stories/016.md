# Story 016: The parsers in src/lib share one prefix helper and one backslash splitter, queryParam matches a name in either case, and src/lib exports only what another file uses

## Symptom

This is a code-quality story (epic/quality: "refactor it. Use dry and all the
best practices"). It continues story 014. No user sees a change, and the
output of each parser stays the same.

On epic/quality (efdac6e) the parsers in src/lib write the same small
helpers again:

1. A prefix test is written by hand nine times: `/^x:/i.test(text)`,
   usually followed by `text.slice("x:".length)`. On one path through
   `classify`, two prefixes are tested twice: `WIFI:` and `MECARD:`.
2. The Wi-Fi parser splits on unescaped `;` and `:` with a loop of its own,
   but contact.ts already has `splitUnescaped` and `unescapeMecard` for the
   same escapes (a backslash before any character).
3. `queryParam` lower-cases the name in the code but not the name the
   caller asks for, so its doc ("Names match in any case") is true only for
   a caller that passes lower case. `percentDecoded` and seven types are
   exported, but only their own file uses them.

## Evidence

I read the code on epic/quality at efdac6e. I did not build, run or measure
anything.

That is nine regex tests and seven slices. These are "the seven prefixes"
below: `mailto:`, `tel:`, `sms:`, `SMSTO:`, `geo:`, `WIFI:`, `MECARD:`.

The review's claim holds. But three existing tests limit how the double
tests can go, and this story may not change them:

- `src/__tests__/wifi.test.ts:41` expects `parseWifi("https://example.com")`
  to be null, and `src/__tests__/contact.test.ts:100` expects
  `parseMecard("WIFI:S:Home;;")` to be null. So `parseWifi` and
  `parseMecard` keep the whole text as input and keep their own prefix test.
  To test `WIFI:` and `MECARD:` only once on classify's path, payload.ts
  needs a function that reads the text after the prefix. The builder
  chooses its name and its shape.
- `src/__tests__/cardLogicSources.test.ts:45-47` requires that payload.ts
  imports wifi.ts and does not contain `function parseWifi`, `unquote` or
  `inValue`.
- `src/__tests__/WifiCard.test.tsx:5` imports `WifiNetwork` from payload.ts,
  so the re-export at `src/lib/payload.ts:10` stays.

`/^BEGIN:VCARD/i` at `src/lib/payload.ts:58` and the line tests at
`src/lib/contact.ts:21-22` are a different kind of check: they do not take
the rest of the text after a prefix. This story does not require a change
to them.

### 2. Backslash splitting

contact.ts has `splitUnescaped` (`src/lib/contact.ts:113-128`) and
`unescapeMecard` (`src/lib/contact.ts:136-138`). The Wi-Fi parser does the
same work in its own loop (`src/lib/wifi.ts:25-43`).

**The review is wrong on one point.** It says that a Wi-Fi field with no
colon can be skipped instead of stored as "", and that the results stay the
same. They do not stay the same. On the base, a field with no colon that ends
at a `;` is stored as "" (`src/lib/wifi.ts:33`), and it **overwrites** an
earlier value with the same key. For example, `WIFI:S:Home;S;;` gives null
today, but if that field is skipped it gives the network "Home". Also, the
last field is dropped when it has no colon and no `;` after it
(`src/lib/wifi.ts:43`), so `WIFI:S:Home;S` gives "Home". The coordinator's intent allowed
the skip only if every result stayed the same. It does not, so **both
behaviours stay**, and rows W8–W10 of AC4 pin them. Neither behaviour is a
product decision for this story.

Other facts that the new parser must keep (all read from
`src/lib/wifi.ts:18-57`):

- Keys are not trimmed.
- Keys are upper-cased with `toUpperCase()`.
- A value is unescaped first, and then unquoted.
- A lone backslash at the end of the text stays in the value.
- The value after the first unescaped `:` keeps its other colons.

### 3. queryParam and exports

`src/lib/query.ts:9` compares `pair.slice(0, eq).toLowerCase()` with `name`
as the caller passed it. The two callers pass lower case, "body"
(`src/lib/sms.ts:24`) and "q" (`src/lib/geo.ts:30`), so no parser output
changes when `name` is lower-cased too. `percentDecoded`
(`src/lib/query.ts:16`) is exported, but only `src/lib/query.ts:9` uses it.

For each export of src/lib/*.ts, I checked every other .ts/.tsx file under
src/, tests included. Eight names have no use outside their own file:
`HeadlineSize` (`src/lib/headline.ts:3`), `Recorded`
(`src/lib/hotkey.ts:12`), `Severity` (`src/lib/urlSafety.ts:4`),
`Assessment` (`src/lib/urlSafety.ts:11`), `Field` (`src/lib/cardModel.ts:8`),
`View` (`src/lib/scanState.ts:4`), `Action` (`src/lib/scanState.ts:21`) and
`percentDecoded`.

**The review named `Warning` too, but `Warning` is used:**
`src/__tests__/tone.test.ts:3` imports it, so it stays exported.

urlSafety.ts has its own `percentDecode` (`src/lib/urlSafety.ts:104`). It
does a different job: it decodes each run of `%XX` separately, but
`percentDecoded` decodes the whole value or nothing. It is part of the mailto
recipient rule (story 010). It is not a duplicate for this story to merge.

### Where the new code goes

To let the instruments find the code, this story sets one place for it: a
new module, src/lib/text.ts. It exports `afterPrefix(text: string, prefix:
string): string | null` and `splitUnescaped` (moved from contact.ts with no
change to its behaviour). The function that removes MECARD/Wi-Fi escapes
(today's `unescapeMecard`) also lives there, under a name the builder
chooses. query.ts is not the place: it is about the `?name=value` part of a
code. `splitOnce` may stay in query.ts or move to text.ts.

The new tests go in five new files, and AC7 refers to them by name:
src/__tests__/text.test.ts, src/__tests__/parserSources.test.ts,
src/__tests__/prefixOnce.test.ts, src/__tests__/wifiTable.test.ts and
src/__tests__/query.test.ts.

## Known weakness of the instrument

- **AC4 proves sameness, not correctness.** It pins today's outputs,
  quirks included: a field with no colon erases an earlier value (W9, W10),
  a key " S" is not S (W19), and ſ reads as S (W18). It covers 26 inputs,
  not all inputs. I got the expected values by reading the code, not by
  running it. The base is the authority (see AC4).
- **AC2 and AC5 prove where code lives. They do not prove that the code is
  good.** They find literals in the AST. A prefix built from pieces
  (`"WI" + "FI:"`), a slice by a number, or a backslash written as
  `String.fromCharCode(92)` or compared as a char code is not found. The
  reviewer reads the diff for those.
- **AC3 counts calls through the module mock.** A call to `afterPrefix`
  from inside text.ts does not go through the mock. A second copy of the
  helper under a different name is AC2's concern, and AC2 finds such a copy
  only by its literals.
- **AC1 pins the helper only for the rows that it lists.** For a prefix that
  contains a `k`, a helper based on `toLowerCase` accepts the Kelvin sign
  (U+212A), but `/i` does not. None of the seven prefixes contains a k, so no
  parser output changes, and AC1 does not test that case.
- **AC7 counts a name as used when another file has an identifier with that
  text, whatever that identifier refers to.** A local with the same name in a
  different file hides an unused export. None of the eight names has such a
  clash today. Exports outside src/lib are not checked.
- **contact.ts's move to the shared splitter has no new sameness table.**
  Only the existing tests check it: `src/__tests__/contact.test.ts`,
  `src/__tests__/payload.test.ts` and `src/__tests__/contactCodes.ts`.
- **The queryParam change has no effect that a user can see today**,
  because both callers pass lower case. AC6 proves the contract of the
  function, not a fix that a user sees.
- **Nothing here runs on a Mac or looks at a card.** The card tests render
  in jsdom.

  src/fonts.css (denied). No rule moves into or out of them, and no
  component uses a name that this story stops exporting.
- The warning rules of src/lib/urlSafety.ts, its `percentDecode` and
  `extraRecipients` (story 010). In that file, only the `export` keyword on
  `Severity` and `Assessment` may change.
- `/^BEGIN:VCARD/i` in payload.ts and the line tests in contact.ts. They do
  not take the rest of the text after a prefix, and they may stay.
- A sameness table for vCard and MECARD. The intent did not ask for one.
- The existing tests in src/__tests__ (denied, each listed in
  `scope_deny`). They are the proof that behaviour stays the same.
  `src/__tests__/sourceText.ts` is the shared helper of the existing source
  tests. New tests may import it, but may not change it.
- core/*, src-tauri/*, site/*, .github/*, scripts/*, README.md, CLAUDE.md,
  AGENTS.md, package.json, package-lock.json, vite.config.ts,
  tsconfig.json, eslint.config.js, index.html, Cargo.toml and Cargo.lock
  (denied). This refactor needs no change to dependencies, configuration or
  documents.
