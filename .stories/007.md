# Story 007: The README and the project page say what the app does now: the new cards, the keys, Find all on screen and the decoy-domain warning

## Symptom

The functional stories are on `epic/docs` (001 to 006). The README and the
project page still describe the app before them:

- The README's opening paragraph (`README.md:3-7`) names Copy and Open, and
  Wi-Fi with Connect. It does not name contacts, phone numbers, SMS or
  locations. It ends "Nothing is copied, opened or joined until you click."
  (`README.md:7`), and that is no longer true: Enter copies, ⌘O opens and
  ⌘J connects.
- "What to check" (`README.md:66-81`) has no check for the new cards, the
  keys, Find all on screen or the decoy-domain warning.
- "How it works" (`README.md:83`) has 004's Find all bullet
  (`README.md:87-91`), but nothing on the new card kinds or the keys. The
  link checks (`README.md:97-100`) do not name the decoy check.
- On the page, step 3 (`site/index.html:207`) says "See the link, text or
  Wi-Fi network. … Nothing happens until you click." Steps 1 and 2
  (`site/index.html:205-206`) do not mention Find all on screen.
- "Checks the link before you do" (`site/index.html:212-227`) has no
  decoy-domain item.
- The page names no key except ⇧⌘2.

## Evidence

I read the code at `epic/docs` (14d505a, the same commit as `develop`).
Nothing was built, run or measured.

### What the app does, from the code

- **Card kinds.** `src/lib/payload.ts:26-35` names them Link, Email, Phone,
  Wi-Fi, Contact, SMS, Location and Text.
  - Contact, from vCard or MECARD: the name, then each phone, email,
    organisation and website, each with its own Copy
    (`src/components/ContactCard.tsx:13-19`). It calls, sends, opens and adds
    nothing.
  - Phone, from `tel:`: the number and Copy number. No Call
    (`src/components/PhoneCard.tsx:10`).
  - SMS, from `sms:` or `SMSTO:`: the number, and the message when there is
    one, each with Copy. No Send (`src/components/SmsCard.tsx:12-19`).
  - Location, from `geo:`: the place or the coordinates, with Copy. Open in
    Maps only for valid coordinates (`src/components/GeoCard.tsx:13`,
    `src/components/GeoCard.tsx:25`). The link is
    `https://maps.apple.com/?ll=<lat>,<lon>`, built from the two numbers
    (`src/lib/geo.ts:37`). It goes through the same `open_link` command,
    and so through the Rust scheme check, as any link
    (`src-tauri/src/commands.rs:40-41`).
- **Keys** (`src/lib/cardKeys.ts:12-16`). The card shows them as keycaps
  beside the buttons, in the mono face (`src/components/Ink.tsx:52-61`).
  Enter shows as ↩ (`src/lib/hotkey.ts:41`).
  - Enter runs the card's main Copy. On a contact that copies the name. On a
    phone or SMS card it copies the number. On a location it copies the
    place or coordinates (`src/components/FieldCard.tsx:51`). On a link or
    text card it copies the text. On Wi-Fi it copies the password, only when
    there is one (`src/components/WifiCard.tsx:51`).
  - ⌘O opens a link that has no warnings, or runs Open in Maps. On a warned
    link it opens nothing and moves focus to Open anyway
    (`src/components/ResultCard.tsx:72-78`, `src/components/ResultCard.tsx:110-121`).
  - ⌘J runs Connect on a Wi-Fi card. It does nothing while connecting or once
    connected (`src/components/WifiCard.tsx:49-51`).
  - A key acts on the card that holds focus, else on the first card
    (`src/components/useCardKeys.ts:9-11`). Enter on a focused button
    presses that button and nothing else
    (`src/components/useCardKeys.ts:29-30`).
- **Find all on screen** is a button under Scan (`src/App.tsx:102-104`)
  and the tray item "Find All Codes on Screen"
  (`src-tauri/src/tray.rs:13-19`).
- **Decoy domains** (`src/lib/urlSafety.ts:57-58`,
  `src/lib/urlSafety.ts:132-144`). A host like
  `paypal.com.secure-login.example.net` gets a danger warning: "This address
  starts with "paypal.com" but belongs to example.net." The card shows

  (`src/__tests__/urlSafety.test.ts:72`). The check is in TypeScript only.

### Where the request and the code differ

1. **The version line has no version.** The request says the line
   "v0.1.2 · one DMG …" stays as it is. No branch has that line.
   `site/index.html:179` reads "One DMG for Apple Silicon and Intel · macOS
   12 or later · free and open source" on `main`, `develop`, `epic/site` and
   `epic/docs`. The intent still holds: the page names no version.
   AC6 keeps that line word for word and forbids a version number anywhere
   on the page.
2. **"A link with a warning opens only on a click" is not quite true.** On a
   warned link ⌘O moves focus to Open anyway, which opens only when it is
   pressed itself: a click, or Enter or Space while it has focus
   (`.stories/005.md:126-127`, `src/components/useCardKeys.ts:29-30`). So
   the true sentence is that a warned link opens only from Open anyway.
   AC1 asks step 3 to name Open anyway. It does not ask for "only on a
   click".
3. **Step 1 already puts a key glyph in Silkscreen.** Step 1's title "Press
   ⇧⌘2" (`site/index.html:205`) is a `.t` span, and `.steps .t` sets the
   pixel font (`site/index.html:125`). The human's rule is "key glyphs in
   Sometype Mono, never Silkscreen; headings and labels stay Silkscreen".
   AC3 applies that rule to every key glyph on the page, so the builder
   puts ⇧⌘2 in step 1's title in the mono face, and "Press" stays in
   Silkscreen. **If the human wants step 1's title left as it is, narrow
   AC3 (b) before promoting.**
4. **The hero's popover copy has no Find all on screen.** The app shows it
   under Scan (`src/App.tsx:102-104`). Story 006's copy does not
   (`site/index.html:194-195`). The human said to keep the hero, so AC6
   keeps it word for word. Updating the copy is a separate decision for the
   human.
5. **The human's own files still say "without a click".** `CLAUDE.md:50`
   and `AGENTS.md:50` say "Nothing opens, copies or joins without a click".
   They are out of scope here. The human may want to change them to match

## Acceptance criteria

The instrument for every AC is a new vitest file under `src/__tests__/`. It
reads `README.md` and `site/index.html` as text with Vite's `?raw` import,
as `src/__tests__/siteReadyPopover.test.ts:7` does. It parses the page with
`DOMParser`. "Text" means `textContent`, lower-cased where a criterion says
case-insensitive, with each run of whitespace made one space. A README
section runs from its heading line to the next heading line named here. If a
heading, element or section a criterion names is missing, the test fails.
It never passes on an empty set.

## Known weakness of the instrument

- **Words, not writing.** These tests prove that named words and structures
  are present in named places. They do not prove that the sentences are
  true, read well, or keep the existing voice. "⌘O never opens anything"
  would pass AC3 (a). A person reads both files against the Evidence above.
- **The declared face, not the drawn one.** AC3 (b) reads which font the
  page's rules declare. It does not resolve the cascade. It asks every
  declaration on the deciding element to agree, rather than working out
  specificity. It stands in for the browser's own stylesheet with a fixed
  list of elements. It cannot see which font draws the glyph.
  - The bundled Sometype Mono subsets do not cover ⌘, ⇧ or ↩
    (`site/index.html:29`). A browser draws those glyphs with the next face
    in `--mono` (ui-monospace, SF Mono on a Mac), as it already does for
    the hero's chip and as the app does.
  - Not observed: how jsdom exposes a `font` shorthand that holds `var()`.
    The red on the base at step 1 is what shows the reader sees
    `.steps .t`'s font. If the reader sees no fonts at all, every glyph
    fails, so the test cannot pass on an empty read.
- **Text, not rendering.** The README is read as Markdown source. A broken
  list or code span shows only when GitHub renders it. The page is not laid
  out: jsdom does no layout. Whether the longer step 3 and the long decoy
  host wrap inside the column on a phone is not tested. (`code` has
  `overflow-wrap: anywhere`, `site/index.html:57`.)
- **The kept parts are kept against the test's own copy.** AC6 (a) compares
  the page with literals copied into the test. If the builder copied a
  changed hero into the test, the guard would protect the wrong text. The
  reviewer diffs those line ranges against `epic/docs`.
- **AC6 (b) catches a version written as x.y.z.** "version 2", or a version
  only in an attribute, would pass.
- **Nothing here is published.** Pages deploys from `main` only
  (`.github/workflows/pages.yml:7-10`). The live site changes when the
  human lands the work.
