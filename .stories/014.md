# Story 014: The cards' display rules move into pure functions under src/lib, ResultCard picks the card with one exhaustive switch, and the four wrapper cards go

## Symptom

On `epic/quality`, the rules that decide what a card shows are in
components. A test on Linux can reach them only by rendering a card.
CLAUDE.md says "Put logic where a test on Linux can reach it"
(`CLAUDE.md:24`).

1. **Four wrapper cards hold display rules.** Each one has the same `Props`
   type (`src/components/ContactCard.tsx:5-9`,
   `src/components/GeoCard.tsx:5-10`, `src/components/SmsCard.tsx:5-9`,
   `src/components/PhoneCard.tsx:4-8`) and renders one `FieldCard`.
   - ContactCard: the order of the rows. Phones, then emails, then
     organisations, then websites (`src/components/ContactCard.tsx:14-19`).
   - GeoCard:
     - the headline is the place, else the coordinates
       (`src/components/GeoCard.tsx:22`);
     - the Copy label follows the headline (`src/components/GeoCard.tsx:23`);
     - a Coordinates row only for a place that is not Android's search
       form (`src/components/GeoCard.tsx:17-18`);
     - Open in Maps only when the parser built a maps link
       (`src/components/GeoCard.tsx:25`).
   - SmsCard: a Message row only when there is a message
     (`src/components/SmsCard.tsx:19`).
   - PhoneCard: only constants (`src/components/PhoneCard.tsx:11-21`).
2. **ResultCard picks the card with an if-chain**
   (`src/components/ResultCard.tsx:26-41`). Two fallbacks are implicit. A
   Wi-Fi code with no network (`src/components/ResultCard.tsx:26`) and a
   phone code with an empty number (`src/components/ResultCard.tsx:32`) go
   to the last line (`src/components/ResultCard.tsx:41`). A new kind of
   payload also goes there, and tsc does not report it. Two smaller faults
   are in the same file:
   - the phone branch of GenericCard's headline
     (`src/components/ResultCard.tsx:55`) cannot run (Evidence, item 2);
   - `.trim()` at `src/components/ResultCard.tsx:32` changes nothing
     (Evidence, item 2).
3. **GenericCard computes its tone and its label itself.** The tone comes
   from the warnings (`src/components/ResultCard.tsx:48-52`). The label adds
   "check before opening" when the tone is not ok
   (`src/components/ResultCard.tsx:57`).
4. **Wi-Fi is the one parser without its own module.** `WifiNetwork`
   (`src/lib/payload.ts:18-24`), `parseWifi` and `unquote`
   (`src/lib/payload.ts:82-127`) are in `payload.ts`. WifiCard keeps the
   `SECURITY` table (`src/components/WifiCard.tsx:18-26`) and builds its
   label (`src/components/WifiCard.tsx:33-34`).

### The contract

The tests below call these names. Other names (types, helpers, test
helpers) are the builder's choice.

- `src/lib/cardModel.ts` exports `fieldCardModel(payload)`. It takes a
  contact, phone, SMS or geo payload and returns:
  ```ts
  {
    meta: string;                              // the card's label
    headline: string;
    copyHeadline: string;                      // the headline Copy's label
    fields: { label: string; value: string }[];
    open: { label: string; url: string } | null;
  }
  ```
- `src/lib/urlSafety.ts` exports:
  - the type `Tone`, `"ok" | "warn" | "danger"`;
  - `toneOf(warnings: Warning[]): Tone`;
  - `linkMeta(label: string, tone: Tone): string`.
- `src/lib/wifi.ts` exports the type `WifiNetwork`, `parseWifi` and
  `wifiMeta(network: WifiNetwork): string`. `src/lib/payload.ts` imports
  `parseWifi` from it.

### No behaviour change, no open question

Each expected value in AC1 to AC3 is what the base shows today, read from
the files cited. The DOM of every card stays the same. 013's DOM guard
(`src/__tests__/cardDom.test.tsx`) and the existing card tests hold it, and
they are denied. This story needs no product decision.

## Known weakness of the instrument

- **Where code lives, not that the DOM is the same.** AC3 (c), AC4 and AC5
  read source text. They prove where a rule is written. The rendered DOM is
  held by 013's DOM guard (`src/__tests__/cardDom.test.tsx`) and by the
  existing card tests (`ResultCard.test.tsx`, `WifiCard.test.tsx`,
  `cardBehaviour.test.tsx`, `App.test.tsx`, `AppKeys.test.tsx`). They are
  denied and must pass as they are. They run in jsdom, not in a browser,
  and nothing is drawn. The DOM guard covers each card in its first state
  only, plus the connecting Wi-Fi card. A hidden network's label on a
  rendered card is held only by W11 and W12 and by WifiCard passing on what
  `wifiMeta` returns.
- **The tsc claim is argued, not observed.** AC5 (a) proves the form of the
  default clause. The baseline build proves that the clause compiles today.
