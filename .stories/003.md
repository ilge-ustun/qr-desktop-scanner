# Story 003: a link that starts with someone else's domain gets no warning

## Symptom

A QR code for https://paypal.com.secure-login.example.net/ gets the card of an
ordinary safe link: no warning, the plain "Link" label, the solid Open button.
The headline is the full hostname, `paypal.com.secure-login.example.net`, which
reads from the left as PayPal. The site belongs to example.net, and nothing on
the card says so.

## Evidence

I traced this by reading the code at `origin/epic/link-checks` (7e940a7). Nothing
was built or run.

- `src/lib/payload.ts:50-51` classifies the text as a `url`, and
  `src/components/ResultCard.tsx:29` passes it to `assess()`
  (`src/lib/urlSafety.ts:36`).
- The scheme is https, so `assess()` skips the early returns at
  `src/lib/urlSafety.ts:46-64` and lowercases the host at
  `src/lib/urlSafety.ts:68`. Then each check misses:
  - userinfo, `src/lib/urlSafety.ts:71-77`: there is no `@`.
  - not-encrypted, `src/lib/urlSafety.ts:78-84`: the link is https.
  - look-alike, `src/lib/urlSafety.ts:85-91`: there is no `xn--` label.
  - ip-address, `src/lib/urlSafety.ts:92-98`: the host is not dotted digits and
    does not start with `[`.
  - shortener, `src/lib/urlSafety.ts:99-105`: the host is not on the list at
    `src/lib/urlSafety.ts:18-32`.

  So `assess()` returns `{ domain: "paypal.com.secure-login.example.net",
  openable: true, warnings: [] }` at `src/lib/urlSafety.ts:106`.
- In `src/components/ResultCard.tsx:31-35`, no warnings means tone "ok", so the
  meta line is plain "Link" (`src/components/ResultCard.tsx:38`). The headline is
  `safety?.domain` (`src/components/ResultCard.tsx:37`), rendered at
  `src/components/ResultCard.tsx:59` in the smallest size, because it is 35
  characters long (`src/lib/headline.ts:8`). The primary Open button is at
  `src/components/ResultCard.tsx:82-84`.
- No existing test covers this. Apart from the IP address 192.168.1.10, no
  hostname in `src/__tests__/urlSafety.test.ts` or
  `src/__tests__/ResultCard.test.tsx` has more than three labels.

Every line number in the request is still correct. One part of the request is
not needed: "the one ResultCard headline change if needed". The headline already
*is* `assess().domain` (`src/components/ResultCard.tsx:37`). When `assess()`
returns the registrable domain, the headline changes without touching the
component, so this story denies `src/components/*`.

### What to build, restating the recorded decisions

The check goes into `assess()`, on the http/https path, after the host is
lowercased at `src/lib/urlSafety.ts:68`.

1. **Registrable domain.** This is the last two labels of the hostname, or the
   last three when the last two are a known two-part public suffix. The
   suffixes are a short constant bundled in `src/lib/urlSafety.ts`, next to
   `SHORTENERS`. The constant contains at least `co.uk`, `com.au`, `co.jp` and
   `com.br`, and the builder may add more two-part suffixes like them. No
   dependency, no network, no full public-suffix database.
2. **Decoy.** The labels in front of the registrable domain contain a label from
   exactly this list: `com`, `net`, `org`, `io`, `co`, `gov`, `edu`. That
   label must not be the first label of the hostname, because it has to come
   after another label. Two-letter country codes are not on the list.
3. **Warning.** A decoy gets exactly one warning, however many labels match:
   `code: "decoy-domain"`, `severity: "danger"`. Keeping it to one also keeps
   the React keys unique, since the card keys warnings by code
   (`src/components/ResultCard.tsx:67`). The message says two things. The
   address starts with the other name, meaning the hostname's labels from the
   start through the first matching label (`paypal.com`). The address belongs
   to the registrable domain (`example.net`). For example: `This address starts
   with "paypal.com" but belongs to example.net.` The builder chooses the exact
   wording. The ACs check only which names it contains.
4. **Headline.** When the warning fires, `domain` is the registrable domain.
   Otherwise `domain` stays the full hostname, as it is now.
   `src/__tests__/urlSafety.test.ts:8-14` and
   `src/__tests__/ResultCard.test.tsx:26-32` rely on that. I read "the card's
   headline then shows that registrable domain" as conditional on the warning.
   Coordinator's choice, under the human's delegation: conditional, as read.
5. **Open.** `openable` stays true. A danger warning already turns Open into
   "Open anyway" (`src/components/ResultCard.tsx:82-89`).

### `app` is not on the list (coordinator's choice)

The request listed `app` as well. With it, any host with a label in front of
`app`, such as staging.app.example.com or eu.app.example.com, would warn: those
are ordinary subdomains of a product's app host, and common. Coordinator's
choice, under the human's delegation: `app` is left out, and AC3 checks that
staging.app.example.com does not warn.

## Acceptance criteria

**AC1 — For the decoy hosts named below, `assess()` returns one `decoy-domain` warning, severity danger, naming both domains.**
Instrument: a test in `src/__tests__/urlSafety.test.ts` that asserts:
(a) for `https://paypal.com.secure-login.example.net/`, the warning codes equal
`["decoy-domain"]`, that warning's severity is `"danger"`, its message contains
`paypal.com` and `example.net` and does not contain `secure-login`, and
`openable` is `true`;
(b) for each label `g` of the seven `com`, `net`, `org`, `io`, `co`, `gov`,
`edu`, the codes for `https://paypal.<g>.secure-login.example.net/`
equal `["decoy-domain"]`;
(c) the codes for `https://paypal.com.google.com.example.net/` (two matching
labels) equal `["decoy-domain"]`.
Goes red when, in `src/lib/urlSafety.ts`: the check is absent (the base, where
the codes are `[]`); the severity is `"caution"`; the message interpolates the
full `host` instead of the two names, so it contains `secure-login`; one of the
seven labels is removed from the list; a warning is pushed for each matching
label instead of once; the check sets `openable` to false.

**AC2 — For the decoy hosts named below, `domain` is the registrable domain, and the card's headline shows it.**
Instrument: tests that assert:
(a) in `src/__tests__/urlSafety.test.ts`, the `domain` of
`assess("https://paypal.com.secure-login.example.net/")` is `"example.net"`;
and for each suffix `s` of the four `co.uk`, `com.au`, `co.jp`, `com.br`,
`assess("https://paypal.com.secure-login.example.<s>/")` has `domain`
`example.<s>` and its codes contain `"decoy-domain"`;
(b) in `src/__tests__/ResultCard.test.tsx`, after rendering the card for
`https://paypal.com.secure-login.example.net/`, the `textContent` of the element
matched by `.headline` (`src/components/ResultCard.tsx:59`) is exactly
`example.net`.
Goes red when, in `src/lib/urlSafety.ts`: `domain` stays `host` (the base, which
fails (a) and (b)); one of the four suffixes is left out of the bundled list (so
`domain` becomes, for example, `co.uk`); the registrable domain is always the
last two labels, ignoring the suffix list; the registrable domain is always the
last three labels (so `domain` becomes `secure-login.example.net`).

**AC3 — paired with AC1 and AC2: the six hosts named below get no warning and keep the full hostname as `domain`.**
Instrument: a test in `src/__tests__/urlSafety.test.ts` that, for each host `h`
of the six `www.example.com`, `mail.google.com`, `a.b.example.co.uk`,
`api.us.example.com`, `co.example.com`, `staging.app.example.com`, asserts that `assess("https://<h>/")`
equals `{ domain: h, openable: true, warnings: [] }`.
Goes red when, in `src/lib/urlSafety.ts`: a two-letter country code such as `us`
is added to the label list (then `api.us.example.com` warns); the check drops
the rule that the label must come after another label (then `co.example.com`
warns); `app` is added to the label list (then `staging.app.example.com`
warns); the decoy labels are taken as those in front of the last label instead
of in front of the registrable domain (then `a.b.example.co.uk` warns on `co`);
`domain` becomes the registrable domain whether or not the warning fires (then
`www.example.com` gives `example.com`).

## Known weakness of the instrument

- **Named hosts only.** The ACs prove the rule on the hosts they name: eight
  distinct hosts in AC1, five in AC2, six in AC3. The rule is a heuristic over two short lists,
  and some tricks get past it by design: the dashed form
  google.com-verify.example.org; a brand with no TLD label after it, as in
  paypal.secure-login.example.net; a country code, as in
  paypal.de.example.net; a TLD that is not on the list, as in
  paypal.shop.example.net.
- **Short suffix list.** When the warning fires for a host under a two-part
  suffix that is not bundled (com.mx, unless the builder adds it), the headline
  shows the last two labels (com.mx) instead of the owner. Hosting suffixes such
  as github.io and web.app are not on the list either, so
  paypal.com.evil.github.io gets the headline github.io, not evil.github.io.
  Only the four suffixes in AC2 are tested.
- **AC3 passes on the base.** The base has no check at all, so AC3 can only go
  red against an implementation that fires too often. Its value lies in the
  mutations it names, together with AC1 and AC2.
- **False positives are not measured** beyond AC3's six hosts. A host with
  another label in front of `co` or `io` (www.co.example.com) warns by design.
- **jsdom does no rendering.** AC2(b) proves the headline's text, not how it
  looks: the Sometype Mono face from `.headline` (`src/styles.css:316-320`), its
  size class, the danger styling. Only a person on a Mac sees those.
- **Not covered:** hostnames with a trailing dot (paypal.com.secure-login.example.net.).
  The URL parser keeps the dot, so the last label is empty and the registrable
  domain comes out wrong. Links whose scheme is not http or https return early
  (`src/lib/urlSafety.ts:46-64`) and never reach the check.
- **No Rust change.** `check_openable` (`core/src/url_guard.rs:22`) checks only
  the scheme. The new warning is advisory: "Open anyway" still opens the link,
  as it does for the other danger warnings.
- **Mocks.** The `assess()` tests mock nothing, since it is a pure function. In
  `src/__tests__/ResultCard.test.tsx` only the callbacks are `vi.fn`.
